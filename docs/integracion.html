Certificados verificables

Una aplicación guiada que relaciona registros, documentos, permisos, consultas y costos. La evidencia se construye ejecutando el caso en una red local.

1. Qué necesita comprobar una organización

Laura terminó un curso y presenta su certificado en una selección. Martín necesita comprobar qué registro le corresponde y si sigue vigente. La institución emisora administra ese registro. No alcanza con que el archivo tenga un logotipo o con que una página diga válido.

El caso utiliza documentos ficticios sin datos personales. En la red local, Ana es la autoridad y Bruno es otra cuenta. El objetivo es seguir la evidencia desde los bytes del archivo hasta el estado del contrato. La práctica no acredita estudios ni ofrece un sistema listo para una institución real.

2. Qué guarda el contrato y qué reglas aplica

Reglas del registro de certificados
Actor y operaciónEstado anteriorResultado
Ana emite una huella nuevaInexistenteVigente, con Ana como emisor.
Bruno intenta emitir o revocarCualquieraNoAutorizado. Se conserva el estado.
Ana emite la misma huella otra vezVigente o revocadoYaRegistrado. Se conserva el estado.
Ana revocaVigenteRevocado. El emisor se conserva.
Ana revocaInexistente o revocadoNoVigente. Se conserva el estado.

La transición es el cambio admitido entre dos estados. Este modelo no permite reactivar un certificado revocado. Corregir el documento cambia sus bytes y requiere otra huella. La política es una decisión del ejemplo, no una obligación de todas las aplicaciones.

El contrato es RegistroCertificados, explicado en la unidad 03. Cada huella tiene emisor y estado. La autoridad es única e inmutable. No hay venta, token, rotación de administradores ni actualizaciones por proxy.

Una misma dirección y un mismo chainId pueden aparecer en redes locales independientes. El archivo de deployment identifica la instancia de esta práctica. El navegador comprueba red, recibo y código antes de habilitar las operaciones. Esas comprobaciones detectan errores de contexto dentro del laboratorio, no certifican la identidad externa del emisor.

3. Relacionar los bytes con el registro

La unidad 03 definió un registro asociado a una huella. Ahora tomamos un archivo de bytes concretos y calculamos SHA-256, el mismo algoritmo de hash utilizado en la primera práctica del curso. Su resultado tiene 32 bytes y puede expresarse con 64 dígitos hexadecimales. El prefijo 0x indica esa representación.

La aplicación lee el archivo seleccionado en la computadora y calcula su huella en el navegador. Para emitir, envía solo esa huella al contrato. El contrato guarda emisor y estado. La versión completa del documento queda fuera de la cadena.

El documento original del ejemplo indica una carga de 20 horas. La versión alterada indica 200. Al cambiar esos bytes cambia la huella. La consulta de la versión alterada devuelve inexistente si nadie registró esa nueva huella. Eso no elimina ni revoca la entrada del original.

Renombrar un archivo sin cambiar sus bytes mantiene su huella. Agregar un espacio o cambiar un salto de línea modifica los bytes y puede cambiarla. En un PDF también puede cambiar información interna que no se ve a simple vista. Esta comprobación compara bytes exactos, no equivalencia visual o significado.

const bytes = await archivo.arrayBuffer();
const digest = await crypto.subtle.digest("SHA-256", bytes);
const huella = "0x" + Array.from(new Uint8Array(digest),
    b => b.toString(16).padStart(2, "0")).join("");

Referencia: Web Crypto: digest. La práctica se sirve desde localhost, donde esta API está disponible en los navegadores utilizados.

Cuatro preguntas diferentes
PreguntaComprobaciónLímite
¿Son los mismos bytes?Calcular la misma huella y compararla con el registro.No prueba que el contenido sea verdadero.
¿El registro está vigente?Consultar el estado en la instancia correcta.Una captura anterior puede estar desactualizada.
¿Puedo obtener el documento?Acceder al archivo en el servicio externo.La cadena no entrega automáticamente ese archivo.
¿Reconozco al emisor?Relacionar la dirección con una autoridad aceptada.Una dirección por sí sola no acredita una institución.

Un documento puede seguir disponible después de revocar su registro. También puede existir un registro vigente mientras el servidor del documento está caído. Cada resultado debe presentarse por separado.

En la aplicación guiada se puede interrumpir la entrega del documento ficticio. El servidor responde HTTP 503 al solicitarlo. El nodo sigue disponible y la consulta de la huella guardada puede seguir indicando vigente. La copia descargada previamente tampoco se borra.

Al restaurar el acceso vuelve a entregarse el mismo archivo. La huella no cambió porque los bytes no cambiaron. En una aplicación real haría falta decidir almacenamiento, copias y responsabilidades de disponibilidad. IPFS es una alternativa posible, pero conservar contenido allí requiere decisiones de persistencia. No se necesita instalarlo para esta práctica.

Referencia: IPFS: persistencia, permanencia y pinning.

4. Preparar y ejecutar la aplicación

Desde la carpeta laboratorio del repositorio del curso, prepará la copia. El preparador conserva una carpeta existente y permite elegir otra con --nombre. Entrega código completo y no inicia servicios.

npm run preparar:certificados
cd practicas/certificados
npm ci
npm run verificar
npm run compilar
npm test

Cada línea se ejecuta por separado. La copia incluye EMPEZAR-AQUI.md, que explica cada paso, su resultado y la comprobación siguiente. Las pruebas inician y cierran su propio nodo temporal.

El contador de 04/05 usa otros puertos y otra instancia. No hay que detenerlo. Las pruebas de certificados usan un nodo temporal en 19646 y tampoco cambian la instancia de la interfaz. Si un puerto está ocupado, se identifica el proceso antes de actuar. No se cierra un servicio ajeno.

Descargá original y alterado desde la aplicación. Conectá como Ana y seleccioná el original. Consultá antes de emitir. Luego intentá emitir como Bruno, emití como Ana, consultá el alterado, intentá un duplicado y una revocación sin permiso. Finalmente revocá como Ana y consultá otra vez.

Antes de revocar, interrumpí la entrega del documento y consultá la huella guardada. Registrá por separado la respuesta del archivo y el estado del contrato. Restaurá el acceso antes de continuar. La guía contiene la matriz de precondición, actor, acción, resultado esperado, observado y evidencia.

npm run recorrido

Este script crea su propia instancia en el nodo de la práctica y deja resultados/recorrido-certificados.json. Muestra 0 → 0 → 1 → 1 → 2 para la huella original y mide emisión y revocación. Los rechazos se prueban antes del envío mediante llamadas de simulación. El script no reproduce la interrupción del archivo ni abre el navegador.

La dirección de ese informe puede ser distinta de la guardada para la página. Comparar ambas permite reconocer qué pertenece a cada ejecución. El comando no reinicia el nodo, no sobrescribe el deployment de la interfaz y no exige fondos reales.
